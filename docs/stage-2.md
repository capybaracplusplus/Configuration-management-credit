# Этап 2: конфигурация и стартовые сценарии

Документ описывает коммит `6b1813f`. Для отдельной копии используйте
`git worktree add ../shell-stage-2 6b1813f`: в той версии ZIP ещё не читается,
а `ls` и `cd` остаются заглушками. Текущие команды описаны в [этапе 4](stage-4.md).

Подготовьте проект командами `make setup` и `make build`. Все примеры ниже
выполняются в настоящем терминале из корня репозитория.

## Параметры запуска

```sh
./run.sh
./run.sh --vfs "/tmp/example archive.zip"
./run.sh --startup-script demos/stage-2.emu
./run.sh --vfs "/tmp/example archive.zip" --startup-script demos/stage-2.emu
```

Проверьте оба значения в отладочном выводе настоящего терминала и в браузере.
На этом этапе путь VFS выводится, но архив ещё не загружается. Относительный
путь отсчитывается от рабочего каталога вызывающего процесса. В каждом сеансе
без завершающего сценария введите `exit`, чтобы перейти к следующему примеру.

## Диалог стартового сценария

```sh
./run.sh --startup-script demos/stage-2.emu
```

1. Убедитесь, что команды появляются в том же диалоге, что и ручной ввод.
2. Проверьте раскрытие `$HOME`, кавычки, пустой аргумент и комментарий после
   команды. Комментарии отдельной строкой и пустые строки пропускаются.
3. Найдите ошибки неизвестной команды, недопустимого параметра `ls`, лишних
   аргументов `cd`/`exit`, незакрытой кавычки и подстановки.
4. Для каждой ошибки проверьте имя файла и правильный номер строки.
5. Найдите последнюю команду `ls after-error`: выполнение после ошибок
   должно продолжаться.
6. Обновите страницу: сценарий не выполняется заново, диалог сохраняется.
7. Введите `exit` вручную.

Номера строк можно сверить в настоящем терминале:

```sh
nl -ba demos/stage-2.emu
```

## Завершение внутри сценария

```sh
./run.sh --startup-script demos/exit.emu
```

Диалог содержит `ls before-exit` и `exit`. Команда с маркером
`NEVER_EXECUTED` не появляется. Ввод отключается, процесс завершается,
а вкладка сохраняет диалог.

## Ошибки конфигурации

```sh
./run.sh --unknown
./run.sh --vfs
./run.sh --startup-script
./run.sh --startup-script /path/that/does/not/exist.emu
```

Первые три запуска заканчиваются с кодом 2; последний — с кодом 1.
Сообщение об ошибке выводится в настоящем терминале, без запуска сеанса.

## Сценарии настоящей ОС

```sh
./scripts/config-valid.sh
./scripts/config-errors.sh
```

Оба сценария определяют корень проекта независимо от текущего каталога.
Временные файлы имеют пути с пробелами и удаляются после проверки.
Созданный ZIP корректен, поэтому эти проверки можно использовать и после
реализации загрузчика VFS.

`config-valid.sh` последовательно проверяет отсутствие параметров, каждый
параметр отдельно и их сочетание, включая сценарий с ошибками команд.
`config-errors.sh` без открытия GUI проверяет точные коды ошибок
и прекращает работу при неожиданном результате.

Во время демонстрации следуйте сообщениям терминала: часть сеансов ожидает
ручной `exit`, а пример `demos/exit.emu` закрывается автоматически.

## Проверки перед коммитом

```sh
make test

```

Сохраните этап отдельным коммитом с описанием параметров, сценариев,
отображения диалога, обработки ошибок и проведённых проверок.
