# Проверка зависаний интерфейса

Проверка выполнена 15 октября 2026 года на macOS после сообщения о том,
что страница перестаёт принимать команды, а браузер Zen продолжает работать.
Использованы установленный Zen 1.23.2b (Gecko 157) с отдельным временным
профилем и видимый Chromium 156.0.8078.4. Проверки проводились интерактивно
через браузерные драйверы с вводом команд, наблюдением страницы и снимками.
Пользовательский профиль Zen не изменялся.

## Воспроизведённые проблемы

1. При открытии шести вкладок постоянные SSE-соединения занимали доступные
   HTTP/1.1-соединения браузера с локальным сервером. Шестая вкладка оставалась
   в состоянии подключения; отправка команды из первой блокировала редактор.
   Сервер оставался готовым, но запрос команды до него не доходил.
   Закрытие шестой вкладки немедленно освобождало запрос.
2. При искусственной задержке HTTP-ответа уже выполненной команды её вывод
   появлялся, но редактор оставался отключённым до получения ответа.
   Состояние отправки зависело от завершения HTTP-запроса, хотя событие
   команды уже подтвердило её принятие.

Падение процесса Python или самого Zen не воспроизведено. Эти два случая
объясняют подтверждённые блокировки страницы; они не доказывают отсутствие
любых других причин зависания.

## Исправления

События браузера переведены на WebSocket. Они используют прежний журнал
и курсор восстановления, не занимая постоянный слот обычного HTTP-запроса.
Сервер проверяет источник подключения, идентификатор сеанса и курсор;
отключение клиента завершает обработчики потока.

HTTP-запросы ограничены пятью секундами. Неопределённый результат позволяет
повторить команду с прежним идентификатором без повторного выполнения.
Событие принятого ввода освобождает редактор независимо от задержки ответа.
Поздний ответ старого запроса не меняет состояние новой команды.

## Повторяемые проверки

`tests/browser/reliability.spec.ts` проверяет восемь вкладок, задержанный ответ
уже принятой команды и повторную отправку запроса после тайм-аута.
Команда при этом должна выполниться один раз.
Весь браузерный набор выполняется в Chromium и Firefox; Firefox проверяет
тот же движок Gecko, но не заменяет отдельную проверку установленного Zen.
Итог: 314 Python-тестов, 32 теста интерфейса и 28 браузерных тестов пройдены.
Статические проверки завершились без ошибок.

```sh
make test
make check
npx playwright install chromium firefox
npm run test:e2e
```

Локальные снимки и измерения находятся в игнорируемых каталогах
`.generated/zen-smoke/`, `.generated/manual-smoke/` и файле
`.generated/manual-websocket-smoke.json`. Они не входят в репозиторий,
поскольку содержат двоичные снимки и данные временного окружения.

Для использования исправления необходимо завершить старый процесс эмулятора
и запустить новую сборку. Простое обновление страницы старого процесса
не обновляет его Python-код.
