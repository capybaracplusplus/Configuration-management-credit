# Архитектура

Один локальный процесс Python хранит сеанс оболочки и выполняет команды.
Браузер отображает состояние и отправляет ввод пользователя. Данные ОС
(`username`, `hostname`, переменные окружения) и параметры запуска читает
процесс Python. Обработчики команд и VFS используют стандартную библиотеку
Python. Минимальная поддерживаемая версия — Python 3.12; проверки проекта
выполнены на Python 3.15.

## Выбор технологий

| Технология | Причина выбора |
| --- | --- |
| Python | Стандартная библиотека содержит средства работы с ZIP, base64, календарём и аргументами процесса. |
| FastAPI и Uvicorn | Обработка HTTP-запросов и WebSocket-соединений, проверка входных данных и запуск локального сервера. |
| Svelte 5 и TypeScript | Компоненты обновляются при изменении состояния; TypeScript проверяет типы данных интерфейса и событий сервера. |
| Vite | Сборка статических ресурсов. В рабочем режиме приложение обслуживает один Python-процесс без отдельного сервера Node.js. |
| HTTP и WebSocket | Команды имеют отдельные запросы; поток событий не занимает постоянный HTTP/1.1 слот каждой вкладки. |

Svelte использует `$state` для локального состояния и `$derived` для значений,
которые вычисляются из него. VFS хранится в Python. Маршрутизация не требуется:
приложение состоит из одного экрана, а серверные обязанности выполняет Python.
Терминал представлен обычным текстом и семантическими HTML-элементами:
программы с управлением курсором и псевдотерминалами не входят в задачу.

## Границы ответственности

| Часть приложения | Отвечает за | Не зависит от |
| --- | --- | --- |
| Обработка команд | Парсер, виртуальные пути, узлы, права, рабочий каталог. | HTTP, браузера, FastAPI. |
| Управление сеансом | Очередь, стартовый сценарий, журнал событий, завершение. | Компонентов Svelte. |
| Ввод и вывод | Чтение ZIP, CLI, данные ОС, HTTP и запуск браузера. | Отображения команд. |
| Браузер | Отображение сеанса, черновик, историю ввода, выделение, фокус и прокрутку. | Внутреннего устройства VFS. |

Обработчик команды возвращает stdout, stderr, код завершения и признак `exit`.
Он не печатает в GUI и не вызывает настоящие программы ОС. Загрузчик ZIP
создаёт виртуальные узлы, с которыми затем работают команды. Содержимое
файлов, в том числе двоичных, хранится в base64.

## Выполнение команды

1. Браузер отправляет строку с идентификаторами сеанса и запроса.
2. Обработчик HTTP-запроса проверяет данные и передаёт команду сеансу.
3. Под блокировкой журналирования приложение проверяет повторный запрос
   и помещает новое задание в FIFO-очередь.
4. Рабочий поток последовательно выполняет команды. Обработка HTTP-запросов
   и доставка событий выполняются отдельно от него.
5. В журнал добавляются ввод, stdout/stderr, результат и новое состояние.
6. WebSocket доставляет события; обработчик TypeScript обновляет состояние,
   а Svelte отображает его.

Повтор запроса с тем же идентификатором и строкой не выполняет команду снова.
Попытка использовать тот же идентификатор для другой команды отклоняется.
Идентификатор сеанса меняется при запуске нового процесса, поэтому старый
браузер не может отправить команду в новый сеанс незаметно для пользователя.

Сервер запускается с одним worker без автоматического перезапуска. Несколько
worker создали бы независимые VFS и нарушили единое состояние сеанса.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/session` | Метаданные, настройки, состояние, снимок журнала и курсор. |
| `POST /api/session/start` | Начать стартовый сценарий один раз после готовности браузера. |
| `POST /api/commands` | Принять строку и стабильный идентификатор запроса; ответ 202. |
| `WS /api/events/ws` | Повторить события после курсора и затем передавать новые в GUI. |
| `GET /api/events` | SSE-поток для диагностических клиентов; браузер его не использует. |
| `POST /api/session/ack-close` | Подтвердить отображение конечного события. |

Снимок и его курсор читаются под одной блокировкой. События, появившиеся после
снимка, доставляются через WebSocket. При переподключении клиент передаёт
последний применённый курсор в параметре `after`. Обработчик браузера
игнорирует уже применённые номера.
Обновление страницы загружает текущий снимок, сохраняя VFS и диалог. Стартовый
сценарий повторно не исполняется.

Постоянный SSE-поток каждой вкладки исчерпывал лимит HTTP/1.1-соединений:
шестая вкладка блокировала отправку команд. WebSocket устраняет эту конкуренцию
за HTTP-слоты, сохраняя серверную очередь и тот же журнал событий.

HTTP-запрос ограничен пятью секундами. При неопределённом результате повтор
сохраняет идентификатор команды. Событие ввода подтверждает принятие команды
и освобождает редактор, даже если отдельный HTTP-ответ задерживается.

Если потерян ответ подтверждения готовности браузера, клиент повторяет
идемпотентный запрос с увеличением задержки до пяти секунд. Повтор не запускает
сценарий снова. Завершение сеанса отменяет таймеры и игнорирует поздние ответы.

Локальный сервер слушает `127.0.0.1`, сам выбирает свободный порт и обслуживает
GUI/API с одного origin. Проверяются допустимые Host и Origin изменяющих
запросов. Приложение не предназначено для многопользовательского хостинга.

## Завершение и ошибки

Стартовый сценарий проходит через тот же движок и очередь. Ошибки содержат
путь и номер строки; следующий шаг продолжается. Интерактивный ввод включается
после окончания сценария. Неожиданная ошибка обработчика не уничтожает
рабочий поток: приложение возвращает диагностику и продолжает сеанс.

`exit` прекращает обработку следующих команд и публикует конечное состояние.
После обновления DOM браузер подтверждает последний курсор. Тогда процесс
завершается; если браузер отключился, завершение происходит через пять секунд.
Этот ограниченный срок позволяет показать последний вывод и одновременно
не оставляет зависший процесс при закрытой вкладке. Вкладка сохраняет текст,
но её ввод отключён; новый сеанс требует нового запуска.

В VFS нет записи обратно в ZIP. `cp` предварительно проверяет весь план
изменений, `chmod` — каждый операнд рекурсивно перед его изменением.
Ошибки проверки не оставляют частично выполненную операцию. Обновление
браузера сохраняет изменения, завершение процесса удаляет их.

## Тесты

pytest проверяет команды, VFS, управление сеансом и API. Vitest проверяет
обработку состояния и компоненты интерфейса. Playwright запускает сервер,
Chromium и Firefox и проверяет выполнение команд через браузер, повторное
подключение, обновление страницы и завершение.
Отдельные проверки сравнивают байты ZIP до/после изменений и загружают его
в новый сеанс, чтобы проверить восстановление исходного состояния.
