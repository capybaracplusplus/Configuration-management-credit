# Этап 3: загрузка ZIP в память

Документ описывает коммит `7e7f78a`. Для отдельной копии используйте
`git worktree add ../shell-stage-3 7e7f78a`. Текущая версия с действующими
`ls`/`cd` демонстрируется по [этапу 4](stage-4.md).

На этом этапе реализован загрузчик VFS. Команды `ls` и `cd` остаются
заглушками до этапа 4: их вывод не является содержимым виртуальных каталогов.

## Подготовка наборов данных

```sh
make setup
make build
make fixtures
```

Архивы генерируются из текстовых описаний в `.generated/vfs/` и не включаются
в Git. Генератор не читает домашний каталог: он создаёт виртуальный путь,
совпадающий с `$HOME`, чтобы позже проверить команду `cd` без аргументов.

| Файл | Назначение |
| --- | --- |
| `minimal.zip` | Пустой ZIP: только виртуальный корневой каталог. |
| `multiple.zip` | Несколько файлов и каталогов, включая двоичное содержимое. |
| `deep.zip` | Вложенное дерево не менее трёх уровней. |
| `invalid.zip` | Намеренно неправильный формат для проверки диагностики. |

В наборе `deep` существует путь `/tree/level1/level2/level3/note.txt`.
Текстовый `/docs/repeated.txt` предназначен также для следующего этапа.
Наборы `multiple` и `deep` содержат `/assets/payload.bin`, скрытый `/.hidden`,
пустой `/empty`, имя с пробелом `/docs/read me.txt` и `/docs/привет.txt`.
Число каталогов зависит от глубины настоящего `$HOME`, имя которого используется
только для создания соответствующего виртуального пути.

## Интерактивная демонстрация

```sh
./scripts/vfs-valid.sh
```

Для каждого из трёх последовательно открываемых сеансов:

1. Проверьте физический путь выбранного ZIP в настройках.
2. Проверьте сводку VFS: число файлов, каталогов и имена объектов в корне.
3. Просмотрите выполнение `demos/stage-3.emu`. Оно включает обычные
   и объединённые параметры `ls`, формы `cd`, переменные, кавычки и комментарии.
4. Убедитесь, что ошибки содержат путь сценария и номер строки, а последняя
   команда `ls after-error` всё равно исполняется.
5. Обновите вкладку: загруженная VFS и диалог не сбрасываются.
6. Введите `exit`, чтобы перейти к следующему архиву.

В итоговую версию дополнительно включена вторая проверка всех трёх допустимых
VFS с автоматическим завершением каждого сеанса:

```sh
./scripts/vfs-smoke.sh
```

Она запускает `demos/vfs-smoke.emu`: подробный список корня, ожидаемая ошибка
пути `/missing`, сообщение о завершении и `exit`. Каждый вызов передаёт
и `--vfs`, и `--startup-script`. Этот краткий сценарий использует готовые
команды итоговой версии и отсутствует в историческом коммите этапа 3.

Отдельный запуск:

```sh
./run.sh --vfs .generated/vfs/deep.zip --startup-script demos/stage-3.emu
```

Отдельная проверка завершения сценария:

```sh
./run.sh --vfs .generated/vfs/deep.zip --startup-script demos/exit.emu
```

Строка после `exit` с маркером `NEVER_EXECUTED` не должна исполняться.

## Ошибки загрузки

```sh
./scripts/vfs-errors.sh
```

Сценарий проверяет отсутствующий и некорректный ZIP как с параметром
стартового сценария, так и без него. Каждый запуск должен вернуть код 1
без открытия GUI. Неожиданный успешный запуск или другой код приводит
к ошибке самого проверяющего сценария.

Загрузчик также отклоняет небезопасные пути, ссылки, повторные ZIP-записи
и конфликты файлов с каталогами. Эти случаи проверяются автоматически.

## Отсутствие изменений исходного ZIP

В настоящем терминале вычислите SHA-256 до и после сеанса:

```sh
shasum -a 256 .generated/vfs/deep.zip
./run.sh --vfs .generated/vfs/deep.zip --startup-script demos/stage-3.emu
shasum -a 256 .generated/vfs/deep.zip
```

После ручного `exit` значения должны совпадать. Файлы архива не распаковываются
на диск: записи, их содержимое base64 и права находятся в памяти процесса.
Полный обход дерева, двоичные данные, неявные родительские каталоги и правила
путей проверяются тестами VFS без использования заглушек команд.
