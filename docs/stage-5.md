# Этап 5: изменение VFS в памяти

Команды `cp` и `chmod` изменяют виртуальные узлы, их содержимое и права.
Исходный ZIP не изменяется и не распаковывается.

## Демонстрация двух сеансов

```sh
make setup
make build
./scripts/mutations.sh
```

Сценарий ОС создаёт архивы, запоминает SHA-256 файла `deep.zip` и открывает
`demos/stage-5.emu`. Ошибки в диалоге намеренные и не останавливают сценарий.
После первого `exit` сравнивается хеш, затем запускается тот же архив
без перегенерации для проверки исходного состояния.

### Первый сеанс

1. Найдите `/copy.txt`: новая копия наследует `0644`, затем получает `0600`.
   Перезапись содержимым `repeated.txt` сохраняет права назначения `0600`.
2. Сравните размеры `/assets/payload.bin` и `/binary-copy.bin`: оба семь байтов.
   Точное совпадение двоичных данных дополнительно проверяется тестами.
3. Проверьте копирование в `/empty`, относительный путь, имена с пробелами
   и `--` для окончания параметров.
4. Найдите `/tree-copy/level1/level2/level3/note.txt`; убедитесь, что повторное
   копирование `/tree` в `/empty` сохраняет добавленный `keep.txt`.
5. Просмотрите изменения прав: восьмеричные числа, `u/g/o/a`, `+/-/=`,
   несколько правил через запятую, несколько путей и рекурсивный `-R`.
6. При `000` файл нельзя прочитать или перезаписать, но `chmod 644` возвращает
   доступ. Каталог без записи запрещает создание, без прохода запрещает
   обращение к детям и изменение их прав.
7. Рекурсивное удаление `u-x` выполняется для всего дерева. Проход
   восстанавливается сверху вниз, после чего рекурсивная команда снова работает.
8. Ошибки количества аргументов, режимов, путей, типов, самокопирования
   и копирования внутрь источника не мешают последним командам сценария.
9. В конце исходный виртуальный `/docs/unique.txt` имеет `0600` и другое
   содержимое. Обновите страницу: изменения и диалог сохраняются.
10. Введите `exit`; настоящий терминал должен показать совпавший SHA-256.

### Второй сеанс

Теперь `/docs/unique.txt` снова имеет `0644` и строки `one`, `two`, `three`.
Файлы `/copy.txt`, `/binary-copy.bin`, `/relative-copy.txt` и каталог
`/tree-copy` отсутствуют: сообщения о ненайденных путях ожидаемы.
После проверки введите `exit`. Сценарий ещё раз сравнит SHA-256 архива.

Для отдельного запуска без второго сеанса:

```sh
make fixtures
./run.sh --vfs .generated/vfs/deep.zip --startup-script demos/stage-5.emu
```

## Правила команд

`cp [-r|-R] ИСТОЧНИК НАЗНАЧЕНИЕ` принимает ровно два пути. При назначении
в существующий каталог используется имя источника. Деревья объединяются;
права новых узлов наследуются, права перезаписываемых узлов сохраняются.
Каталог требует `-r` или `-R`. Запись в исходное дерево запрещена даже при
сложном пересечении путей через объединение с предком. Допустимое объединение
не затрагивает исходные узлы. Перед применением проверяется весь план:
ошибка не оставляет частичных копий.

`chmod [-R] РЕЖИМ ПУТЬ ...` принимает `000`–`777` и четырёхзначную форму
с ведущим нулём. Символьная форма требует явные классы `u`, `g`, `o` или `a`
и допускает только `r`, `w`, `x` с операциями `+`, `-`, `=`. Например:

```text
chmod u=rw,g=r,o= /copy.txt
chmod a+r /copy.txt
chmod g+w,o-r /copy.txt
chmod -R u+w /tree-copy
```

Пустые `u+` и `u-` допустимы и не меняют права; `u=` очищает соответствующие
биты. `+r` без класса, `X`, `s` и `t` не поддерживаются. Все пути относятся
к виртуальной системе; истинный пользователь ОС не получает особых привилегий.

Для рекурсивного изменения сначала собираются доступные узлы одного операнда,
затем меняются права. Ошибка проверки оставляет этот операнд неизменным,
после чего команда продолжает обработку других переданных путей.

## Порядок демонстрации

1. Покажите пять этапов в `git log --oneline` и подробное сообщение одного
   коммита: `git show --no-patch --format=fuller 516d655`.
2. Покажите реальный заголовок, параметры запуска и сводку ZIP.
3. Выполните `./scripts/commands.sh`: парсер, основные команды и ошибки.
4. Выполните `./scripts/mutations.sh`: копирование, права, сохранение после
   обновления страницы, неизменность ZIP и восстановление при новом процессе.
5. Покажите результаты автоматических проверок и устройство приложения
   в [описании архитектуры](architecture.md).

Исторические этапы 1–4 воспроизводятся в отдельных рабочих каталогах Git;
их коммиты указаны в [README](../README.md). Старые инструкции о заглушках
относятся именно к тем версиям.

## Автоматические проверки

```sh
make test
make check
make build
make fixtures
npx playwright install chromium firefox
npm run test:e2e
```

Проверяются двоичные копии, перезапись, наследование прав, рекурсивное
объединение, недопустимые пересечения, отказы доступа, атомарность проверки,
изменение нескольких путей, восстановление состояния и исходные байты ZIP.
