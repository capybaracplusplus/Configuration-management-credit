# Эмулятор командной оболочки — вариант 12

Учебный эмулятор UNIX-подобной командной оболочки с графическим интерфейсом
в браузере. Локальный Python-процесс исполняет команды и хранит состояние
сеанса; Svelte-интерфейс отображает ввод, вывод и ошибки.

Поддерживаются параметры запуска, стартовые сценарии, виртуальная файловая
система (VFS) из ZIP и команды `ls`, `cd`, `echo`, `uniq`, `cal`, `cp`,
`chmod`, `exit`.
Изменения файлов и прав существуют только в памяти текущего сеанса.

Реализация охватывает все пять этапов варианта 12. Пошаговые сценарии
проверки и ожидаемые результаты приведены в документации: от
[этапа 1](docs/stage-1.md) до [этапа 5](docs/stage-5.md).

## Архитектура

- Обработка команд: парсер, диспетчер команд и состояние оболочки на Python.
  Этот код не зависит от HTTP или браузерных компонентов.
- Управление сеансом: последовательное выполнение команд, история
  диалога и завершение процесса.
- Ввод и вывод: FastAPI/Uvicorn, чтение ZIP, данные ОС и параметры запуска.
- Интерфейс: Svelte 5, TypeScript и Vite. Отправляет команды по HTTP
  и получает события через WebSocket с восстановлением по курсору.

Один процесс соответствует одному сеансу. Обновление страницы восстанавливает
его историю; оно не создаёт новый сеанс. Команды не запускают программы
настоящей ОС. Сервер слушает только локальный адрес `127.0.0.1`.
Обоснование технологий, границы слоёв и протокол: [архитектура](docs/architecture.md).

## Подготовка и запуск

Требуются Python 3.12+ и Node.js 22.12+ с npm. Проверенное окружение:
Python 3.15 и Node.js 26. Python не требует компиляции; перед запуском
необходимо собрать браузерную часть.

```sh
make setup
make build
make fixtures
./run.sh --vfs .generated/vfs/deep.zip
```

Приложение выводит локальный URL и открывает браузер. Если автоматическое
открытие недоступно, откройте напечатанный адрес самостоятельно. Порт выбирается
автоматически. Заголовок страницы содержит реальное имя пользователя
и имя компьютера: `Эмулятор - [username@hostname]`.

| Команда | Назначение |
| --- | --- |
| `make setup` | Установить зависимости Python и браузерной части. |
| `make build` | Собрать Svelte-интерфейс в статические файлы. |
| `make run` | Запустить собранное приложение. |
| `make fixtures` | Создать демонстрационные ZIP из текстовых описаний. |
| `make test` | Выполнить Python-тесты и тесты интерфейса Vitest. |
| `make check` | Выполнить статические проверки и проверку оформления. |
| `npm run test:e2e` | Проверить запущенное приложение в Chromium и Firefox. |

## Интерфейс и язык команд

Введите команду и нажмите Enter. Стрелки вверх/вниз позволяют просматривать
историю и возвращаться к незавершённому вводу. Текст диалога можно выделять
и копировать. Когда пользователь читает предыдущие строки, новые сообщения
не должны перемещать его к концу истории.

Одна интерактивная команда ограничена 65536 символами. Более длинный ввод
не обрезается: интерфейс показывает ошибку и сохраняет строку для исправления.

### Парсер

- Подстановка переменных настоящего окружения: `$HOME`, `${HOME}`.
- Одинарные кавычки сохраняют текст буквально: `'$HOME'`.
- Двойные кавычки сохраняют раскрытую переменную одним аргументом: `"$HOME"`.
- Незакавыченное раскрытие допускает разделение аргументов пробелами.
- Поддерживаются экранирование и пустые аргументы `""` и `''`.
- Неопределённая переменная раскрывается в пустую строку.
- `#` вне кавычек начинает комментарий.
- Пустая строка не является ошибкой.

Незакрытые кавычки, некорректная подстановка, неизвестная команда и неверные
аргументы вызывают диагностическое сообщение, после которого можно продолжить
работу. Конвейеры, перенаправления, шаблоны файлов, подстановка команд и запуск
программ настоящей ОС не входят в поддерживаемый язык.

### Команды

| Команда | Поддерживаемые режимы |
| --- | --- |
| `ls [-a] [-l] [ПУТЬ ...]` | Отсортированные имена; `-a` добавляет скрытые записи, `.` и `..`; `-l` показывает тип, права и размер в байтах. |
| `cd [ПУТЬ]` | Переход по абсолютному/относительному пути; без аргумента — виртуальный `$HOME`; `-` возвращает предыдущий каталог. |
| `echo [-n] [АРГУМЕНТ ...]` | Аргументы через пробел; `-n` убирает конечный перевод строки. |
| `uniq [-c] [-d\|-u] ФАЙЛ` | Соседние одинаковые строки: `-c` считает, `-d` оставляет повторяющиеся группы, `-u` — одиночные. |
| `cal [ГОД]` / `cal МЕСЯЦ ГОД` | Текущий месяц, весь год или выбранный месяц; неделя начинается с воскресенья. |
| `cp [-r\|-R] ИСТОЧНИК НАЗНАЧЕНИЕ` | Копирование файла, перезапись, копирование в каталог; `-r`/`-R` копирует дерево рекурсивно. |
| `chmod [-R] РЕЖИМ ПУТЬ ...` | Восьмеричные или символьные права; `-R` применяет их к дереву. |
| `exit` | Завершить сеанс и локальный процесс. Аргументы не принимаются. |

`ls`, `uniq` и `cp` допускают объединённые параметры: `-al`, `-cd`, `-rR`.
Команды с путями принимают `--` для окончания списка параметров. `echo`
тоже принимает `--`; остальные аргументы, кроме ведущего `-n`, печатаются
буквально. Escape-последовательности вида `\n` команда `echo` не интерпретирует.

Рабочий каталог начинается с `/`. Компоненты `.` и `..` разрешаются внутри
VFS; выше корня перейти невозможно. `cd` не обращается к настоящим каталогам:
если соответствующего `$HOME` нет в архиве, команда сообщает об ошибке.
Файлы для `uniq` должны быть UTF-8; чтение из стандартного ввода не реализовано.
Одинаковые строки в разных группах не объединяются. `-d` и `-u` несовместимы,
но каждый из них можно сочетать с `-c`.

Календарь имеет английские заголовки для одинакового результата независимо
от локали ОС. Допустимы месяцы 1–12 и годы 1–9999. Без аргументов используется
текущая дата локальной ОС.

`cp` принимает ровно два пути. Новая копия наследует права источника,
перезапись сохраняет права назначения. При копировании каталога в существующий
каталог создаётся или объединяется дочерний каталог с именем источника.
Самокопирование, запись внутрь исходного дерева и конфликты типов отклоняются.
Перед изменением проверяется весь план копирования: ошибка не оставляет
частично скопированное дерево.

`chmod` принимает режимы `000`–`777` с необязательным ведущим нулём, например
`0644`, и символьные правила `u/g/o/a`, `+/-/=`, `rwx`, например
`u=rw,g=r,o=`. Классы пользователей должны быть указаны явно; `+r`, `X`, `s`
и `t` не поддерживаются. Пустые `u+` и `u-` ничего не меняют; `u=` очищает
биты владельца. Несколько правил разделяются запятой.

Операции используют права виртуального владельца: чтение, запись и проход
по каталогам. `chmod` может восстановить права файла или самого каталога
после `000`, если доступен путь к его родителю. Рекурсивный режим сначала
проверяет и собирает всё дерево, затем изменяет права. Каждый операнд
обрабатывается независимо: ошибка одного пути не отменяет остальные.

После `exit` вкладка сохраняет последний диалог и отключает ввод. Сервер
завершается после подтверждения отображения последнего события браузером
или по истечении пяти секунд. Для нового сеанса запустите `./run.sh` повторно.

```text
ls
ls -al /docs
cd /tree/level1/level2/level3
ls -l note.txt
cd -
echo "$HOME" '$HOME' "имя с пробелами"
uniq -c /docs/repeated.txt
cal 2 2024
cp /docs/unique.txt /copy.txt
chmod 0600 /copy.txt
ls -l /copy.txt
unknown
exit unexpected
exit
```

Примеры режимов и ошибок: [демонстрация этапа 4](docs/stage-4.md)
и [сценарий основных команд](demos/stage-4.emu),
[демонстрация этапа 5](docs/stage-5.md) и [сценарий изменений](demos/stage-5.emu).

## Конфигурация и стартовые сценарии

```sh
./run.sh [--vfs ПУТЬ] [--startup-script ПУТЬ]
make fixtures
./run.sh --vfs .generated/vfs/deep.zip
./run.sh --startup-script demos/stage-2.emu
./run.sh --vfs .generated/vfs/deep.zip --startup-script demos/stage-5.emu
```

Оба параметра необязательны. Пути относятся к настоящей ОС и разрешаются
относительно каталога, из которого запускается команда. Значения параметров
отображаются при запуске в терминале и браузере. Параметр `--vfs` задаёт ZIP
виртуальной файловой системы. Без него создаётся пустой виртуальный корень.

Стартовый сценарий — текстовый файл UTF-8 с одной командой на строку.
Пустые строки и комментарии `#` пропускаются; комментарии после команды
обрабатываются парсером, а `#` в кавычках остаётся частью аргумента.
В браузере отображаются и введённые команды, и результаты их выполнения.
Сценарий запускается один раз после готовности браузера; ввод на время
его исполнения отключён. Обновление страницы не запускает сценарий повторно.

Ошибка команды содержит путь сценария и номер строки. Выполнение продолжается
со следующей строки. Команда `exit` останавливает сценарий и завершает процесс;
строки после неё не исполняются. Ошибка чтения сценария завершает запуск
с кодом 1, ошибка синтаксиса параметров — с кодом 2.

```sh
./scripts/config-valid.sh
./scripts/config-errors.sh
```

Первый сценарий ОС проверяет запуск без параметров, каждый параметр отдельно,
их сочетание, пути с пробелами и ошибки исполнения. Второй без открытия GUI
проверяет неверные параметры и ошибки чтения. Окна открываются последовательно: если демонстрация
не завершилась автоматически, введите `exit` после просмотра диалога.
Пошаговая проверка: [этап 2](docs/stage-2.md).

## Виртуальная файловая система

ZIP читается непосредственно в память. Приложение не распаковывает его
на диск и не изменяет исходный архив. Содержимое файлов хранится в base64,
каталоги и UNIX-права — в отдельных метаданных. Пропущенные записи родительских
каталогов создаются в памяти. Пути VFS используют `/`, независимо от ОС.

При загрузке проверяются формат архива, корректность путей, повторные записи,
конфликты файлов с каталогами и символьные ссылки. Недопустимый или отсутствующий
ZIP приводит к сообщению об ошибке в терминале и завершению с кодом 1.
Имеющиеся UNIX-права сохраняются; по умолчанию используются `0755` для каталогов
и `0644` для файлов.

Браузер показывает сводку загруженной VFS: число файлов и каталогов, а также
имена объектов в корне. Команды `ls` и `cd` используют это дерево. Проверяются
права единственного виртуального владельца: чтение файлов/списков каталогов,
запись и проход по каталогам. Права настоящего пользователя ОС на VFS не влияют.
Обновление страницы сохраняет изменения VFS; завершение процесса их удаляет.
При следующем запуске исходный ZIP читается заново.

```sh
make fixtures
./scripts/vfs-valid.sh
./scripts/vfs-smoke.sh
./scripts/vfs-errors.sh
```

Генератор создаёт в `.generated/vfs/` минимальный архив, архив с несколькими
файлами, архив с деревом глубже трёх уровней и файл неправильного формата.
ZIP исключены из Git; исходные описания являются текстовыми. Каталоги,
соответствующие реальному `$HOME`, создаются виртуально без чтения его файлов.
Два сценария ОС проверяют все три допустимых варианта: `vfs-valid.sh` оставляет
каждый сеанс для ручного просмотра, а `vfs-smoke.sh` выполняет краткую проверку
итоговой версии и автоматически завершает каждый сеанс командой `exit`.
`vfs-errors.sh` отдельно проверяет неправильные и отсутствующие архивы.
Подробная демонстрация: [этап 3](docs/stage-3.md).

## Проверка основных команд

```sh
./scripts/commands.sh
```

Сценарий ОС создаёт наборы данных и открывает VFS `deep.zip` со стартовым
сценарием этапа 4. После исполнения просмотрите диалог, введите команды вручную
и завершите сеанс командой `exit`. Ошибки в демонстрации ожидаемы: они проверяют
диагностику и продолжение выполнения.

## Проверка изменений VFS

```sh
./scripts/mutations.sh
```

Сценарий проверяет режимы `cp`/`chmod`, ошибки прав и восстановление доступа.
После ручного `exit` он сравнивает SHA-256 исходного ZIP и открывает
новый сеанс для проверки исходных данных и отсутствия сделанных копий.
Подробные ожидаемые результаты и порядок защиты: [этап 5](docs/stage-5.md).

Для защиты сначала покажите настройки и заголовок, затем диалог
`scripts/commands.sh`, диалог `scripts/mutations.sh`, результаты тестов
и историю `git log --oneline`. Старые этапы воспроизводятся в отдельных
рабочих каталогах по коммитам, приведённым ниже.

## Тестирование и оформление

Результаты проверки зависаний в Zen, проверки API и объяснение исправлений:
[отчёт о проверке](docs/smoke-test.md).

Python-тесты проверяют парсер, команды и приложение без открытия браузера.
Vitest проверяет состояние интерфейса и компоненты; Playwright проверяет
приложение через настоящий браузер. Проверки охватывают повторную отправку
запросов, последовательное выполнение, восстановление событий и завершение.
Проверки изменений сравнивают байты исходного архива, состояние VFS после
перезапуска, восстановление прав и отсутствие частичных изменений при ошибке.

```sh
make test
make check
make build
make fixtures
npx playwright install chromium firefox
npm run test:e2e
```

Установка браузеров требуется один раз для браузерных тестов. Playwright
сам запускает локальные процессы приложения; заранее открывать GUI не нужно.
Снимки экрана и результаты находятся в игнорируемом каталоге `test-results/`.

Структурная проверка учитывает отслеживаемые Git-файлы и новые неигнорируемые
файлы. Ограничения: 1000 строк на файл, 80 столбцов для Python/JavaScript/
TypeScript, 120 столбцов для остальных исходников, 40 строк и 7 параметров
на функцию. Сложность, стиль и документация проверяются линтерами.

Зависимости, результаты сборки, архивы, двоичные файлы и локальные настройки
не включаются в Git. Файлы фиксации зависимостей являются текстовыми данными.
